## 1. Admin ใช้ 2FA flow เดียวกับ Supervisor

### สิ่งที่เปลี่ยน
- Admin สามารถเปิด Two-Factor Authentication (Google/Microsoft Authenticator) ได้แล้ว
- Flow เดียวกับ Supervisor:
  1. Login ด้วย email/password
  2. ถ้ายังไม่เปิด 2FA → ถูก redirect ไป `/2fa-setup`
  3. สแกน QR / กรอก secret
  4. กรอก OTP 6 หลักเพื่อเปิดใช้งาน
  5. บันทึก Recovery Keys (8 รหัส)
  6. ระบบ logout → login ใหม่ → `/2fa-challenge` → กรอก OTP → เข้า Dashboard
- Admin ที่เปิด 2FA แล้วสามารถใช้ Forgot Password ได้ 2 วิธี:
  - OTP จาก Authenticator
  - Recovery Key
- Admin ที่ยังไม่เปิด 2FA ยังใช้ OTP ทางอีเมลในหน้า Forgot Password เหมือนเดิม
  - ⚠️ พฤติกรรมนี้ถูกเปลี่ยนแล้วใน `docs/2026-11-15-2fa-bootstrap-flow.md` (ลบ email OTP)

### ผลกระทบสำคัญ
- **Admin ทุกคนที่ยังไม่เปิด 2FA จะถูกบังคับตั้งค่าใน login ครั้งถัดไป**
- ต้องมีแอป Authenticator และต้องเก็บ Recovery Keys ให้ดี
- ถ้าเสียทั้งมือถือและ Recovery Keys ต้องให้ผู้ดูแลระบบแก้ที่ฐานข้อมูล

### หมายเหตุด้านความปลอดภัย
- การบังคับ 2FA เป็นการบังคับฝั่ง frontend (`ProtectedRoute`) เหมือน Supervisor
- Backend login ยังออก token ปกติถ้า `twoFactorEnabled = false`
- ⚠️ ข้อจำกัดนี้ถูกปิดแล้วในภายหลัง — ดู `docs/2026-11-15-2fa-bootstrap-flow.md`
  (มี bootstrap gate ที่ `backend/middlewares/auth.ts` + ลบ email OTP ทั้งระบบ)

### ไฟล์ที่เกี่ยวข้อง

- `frontend/src/routes/ProtectedRoute.tsx`

## 2. Admin จัดการ Footer / Popup / ประวัติได้

### สิ่งที่เปลี่ยน
- Route ต่อไปนี้เปลี่ยนจาก `requireSupervisor` เป็น `requireAdmin` (ADMIN + SUPERVISOR):
  - `PUT /api/settings` (Footer, นโยบาย, ประวัติ)
  - `GET/POST/PUT/DELETE /api/splash-popups` (ยกเว้น `/active` ที่ public)
- Admin จึงแก้ Footer, Popup เปิดหน้า และประวัติได้แล้ว โดยยังมี audit log ทุกครั้ง

### Bug ที่แก้ไปด้วย
- **ประวัติ**: ปุ่ม "ล้างเนื้อหา" เดิมล้างแค่ state ในหน้า admin ไม่บันทึก DB
  - ตอนนี้เรียก `PUT /api/settings` ด้วยค่า `about_history = ""` จริง
- **Footer**: เดิมกรองค่าว่างทิ้ง ทำให้ลบค่าในฟิลด์ไม่ได้
  - ตอนนี้ส่งเฉพาะ field ที่เปลี่ยน และส่งค่าว่างได้เพื่อล้างค่า

### ไฟล์ที่เกี่ยวข้อง
- `backend/routes/footerSettingRoute.ts`
- `backend/routes/splashPopupRoute.ts`
- `frontend/src/components/dashboard/AboutHistoryManager.tsx`

## 3. Popup เปิดหน้า — แก้รูปภาพได้แล้ว

### สิ่งที่เปลี่ยน
- หน้าแก้ไข Popup แสดงเครื่องมือ crop 4:5 จริง
- รองรับ:
  - เลือกรูปใหม่
  - ตัด 4:5 / ใช้รูปเต็ม / ตัดใหม่
  - ลบรูปที่เลือก
- Frontend ส่ง `FormData` (title + image) ไป `PUT /api/splash-popups/:id`
- Backend:
  - รับไฟล์ `image`
  - ตรวจ MIME + magic bytes
  - แปลงเป็น WebP
  - อัปเดต `image_url`
  - ลบไฟล์รูปเก่าออกจาก `uploads/`
  - ถ้า DB update fail จะลบไฟล์ใหม่ที่อัปโหลดมา

### Migration ที่เกี่ยวข้อง
- `backend/prisma/migrations/20261109000000_add_splash_popup_bg_color/migration.sql`
- เพิ่มคอลัมน์ `bg_color` ที่มีใน `schema.prisma` แต่ขาดจาก migration เดิม
- ใช้ `ADD COLUMN IF NOT EXISTS` เพื่อรองรับ DB ที่เคย `prisma db push`

### ไฟล์ที่เกี่ยวข้อง

- `frontend/src/services/contentService.ts`
- `backend/controllers/splashPopupController.ts`

## 6. `/sitemap.xml` (XML สำหรับ Search Engine)

### สิ่งที่เพิ่ม
- Backend endpoint: `GET /sitemap.xml`
- Controller: `backend/controllers/sitemapController.ts`
- Route: `backend/routes/sitemapRoute.ts`
- Mount ใน `backend/server.ts`

### เนื้อหา sitemap
- Static routes:
  - `/`
  - `/news`
  - `/advertise`
  - `/about/history`
  - `/contactform`
  - `/commentform`
  - `/sitemap`
- Dynamic routes:
  - `/department/:id` (เฉพาะ `isDelete = false`)
  - `/news/:id` (เฉพาะ `type = NEWS` และ `isShow = true`)
  - `/advertise/:id` (เฉพาะ `type = PR` และ `isShow = true`)
- มี `lastmod` สำหรับข่าว/PR (ใช้ `date`) และ `changefreq` / `priority`

### Base URL
- ถ้าตั้ง `SITE_URL` → ใช้ค่านั้น
- ถ้าไม่ตั้ง → ใช้ `Host` + `X-Forwarded-Proto` ของ request
- ตัวอย่าง:
  ```env
  SITE_URL=https://www.amlo.go.th
  ```

### Nginx
- เพิ่ม exact location ใน `frontend/nginx.conf`:
  - `/sitemap.xml` → proxy ไป backend
  - cache 1 ชั่วโมง
- ต้อง rebuild frontend image หรืออัปเดต `nginx.conf` ใน container แล้ว reload Nginx

### Vite dev
- เพิ่ม proxy `/sitemap.xml` ใน `frontend/vite.config.ts`
- Docker dev ตั้ง `VITE_SITEMAP_PROXY_TARGET=http://backend:8080` ใน `docker-compose.dev.yml`

### Vercel
- Config Nginx ใช้กับ Docker เท่านั้น
- ถ้า deploy บน Vercel ต้องเพิ่ม rewrite/proxy `/sitemap.xml` ไป backend เอง
- หรือใช้ reverse proxy หน้าบ้าน

## 10. ขั้นตอน Deploy

1. **Backup ฐานข้อมูลก่อน**
   - ใช้ฟีเจอร์ Backup ใน Dashboard หรือ
   ```bash
   docker compose exec -T postgres pg_dump -U postgres backend_amlo > backup_before_update.sql
   ```
   แนะนำให้ backup ก่อน migrate ทุกครั้ง

2. **Pull code + submodules**
   ```bash
   git pull --recurse-submodules
   ```

3. **Rebuild backend + frontend**
   ```bash
   docker compose up -d --build backend frontend
   ```
   - backend container จะรัน `npx prisma migrate deploy` อัตโนมัติจาก CMD ใน Dockerfile
   - frontend ต้อง rebuild เพื่อเอา `nginx.conf` ใหม่ (proxy `/sitemap.xml`) และ `robots.txt`

4. **ตรวจ migration (หลัง rebuild)**
   ```bash
   docker compose exec backend npx prisma migrate status
   ```
   - migration ใหม่: `20261109000000_add_splash_popup_bg_color`
   - ถ้าต้องการรัน manual: `docker compose exec backend npx prisma migrate deploy`
   - ถ้า `prisma migrate status` ฟ้องว่า DB ไม่ตรง history ให้ backup + baseline ก่อน
   - ถ้า DB เคย `db push` มาก่อน migration จะใช้ `ADD COLUMN IF NOT EXISTS` ช่วยไว้

5. **ตรวจ Nginx**
   - ต้องมี location `/sitemap.xml` ใน `frontend/nginx.conf`
   - ถ้า deploy แบบ `docker cp` + reload Nginx ให้ copy `nginx.conf` ใหม่เข้า container ด้วย

6. **ตั้งค่า `SITE_URL` (ไม่บังคับแต่แนะนำ)**
   ```env
   SITE_URL=https://www.amlo.go.th
   ```
   - ใช้สร้าง absolute URL ใน `/sitemap.xml`
   - ถ้าเว้นว่างจะใช้ Host ของ request

7. **แก้โดเมนใน `robots.txt`**
   - ถ้า production ไม่ใช่ `https://www.amlo.go.th`
   - แก้ `frontend/public/robots.txt` แล้ว rebuild frontend

8. **Vercel**
   - ถ้า deploy frontend บน Vercel ต้องเพิ่ม rewrite/proxy `/sitemap.xml` ไป backend
   - Nginx config ใช้กับ Docker เท่านั้น

## 12. Known Limitations

- การบังคับ 2FA เป็น client-side (ProtectedRoute) — API ยังไม่บังคับที่ middleware
- ยังไม่มี RSS feed generator — `rss_url` เป็นลิงก์ภายนอกที่ admin ใส่เอง
- ยังไม่มีหน้า policy/bookguide ภายในเว็บ — ใช้ลิงก์ภายนอกผ่าน Footer Manager
- `/sitemap.xml` บน Vercel ต้องตั้ง rewrite/proxy เอง
- Lint ของโปรเจกต์ยังมี rule เดิม `react-hooks/set-state-in-effect` ในบางไฟล์ (ไม่เกี่ยวกับรอบนี้)
- `Reports/` ถูก gitignore — เอกสารนี้อยู่ใน `docs/` เพื่อให้ track ได้
